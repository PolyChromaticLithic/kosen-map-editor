# 校内マップ データエディター

`campus_map_database_design.docx` (v1.0) のデータを編集するためのブラウザ用ツールです。
Supabaseには直接つながず、**CSVを読み込んで編集し、CSVで書き出して**Supabaseに取り込みます。

| 編集できる | 読み取りのみ（参照用） |
|---|---|
| place_locations / route_nodes / route_edges / place_access_nodes / route_node_map_positions | buildings / floors / floorplans / places / place_aliases |

## 起動

```sh
cd editor
npm install
npm run dev        # http://localhost:5173
npm test           # ユニットテスト
npm run build      # dist/ に静的ファイルを出力
```

## 基本の流れ

1. Supabaseの Table Editor から各テーブルをCSVでエクスポートする（`places_rows.csv` のようなファイル名のままで構いません）
2. 「読み込み…」を押すか、画面にファイルをドロップする。次の種類をまとめて渡せます
   - CSV（ファイル名からどのテーブルか判別します）
   - GLB / glTF（`.gltf` の場合は `.bin` とテクスチャも一緒に）
   - 平面図SVG（`floorplans.asset_path` とファイル名が一致すれば自動で割り当てます）
   - `editor-project.json`（エディター設定）
   - 上部の「テーブル n/10」ボタンで、読み込めるテーブルの一覧と、それぞれ読み込み済みか（ファイル名・件数・日時）を確認できます
3. 編集する（後述）
4. 「CSV書き出し (ZIP)」を押す。中の `README.txt` の手順でSupabaseに反映する
   - 初回のみ `00_once_identity.sql` を実行する（IDを明示して投入できるようにするため）
   - `01_clear.sql` → CSVを順に取り込む → `02_after_import.sql`

作業内容はブラウザ（IndexedDB）に自動保存され、再読み込みしても続きから作業できます。

## 画面と操作

- **作業階**：選んだ平面図の高さにグリッドが出て、クリック位置はその高さで決まります。「屋外 / 全体」ではモデル表面に置きます
- **ツール**（キーボードでも切替可）
  - `V` 選択/移動：ギズモで動かします。階に属するものは水平方向にしか動きません
    - ノードの球・場所のピンは、そのままドラッグしても動かせます（ノードは `N` ノード追加中、ピンは `P` 場所を配置中も可）。高さは変わりません
    - ノードや場所のピンを**右クリック**すると基準になります（ピンクの輪。もう一度右クリックで解除）。他のノード・場所を動かすと、基準の X / Y / Z に近づいた軸が吸着し、軸の色の点線が出ます。`Alt` を押している間は吸着しません
  - `P` 場所を配置：左の一覧で場所を選んでから床をクリックします
    - どのツールでも、左の一覧から場所を3Dビューへ**ドラッグ&ドロップ**して配置できます。高さはその場所の階（屋外ならモデル表面）になり、作業階もその階に切り替わります
    - 一覧の「作業階のみ」で、作業階の場所だけに絞り込めます（「屋外 / 全体」のときは屋外の場所）
  - `N` ノード追加：`Shift`+クリックで、選択中のノードからエッジも続けて張ります。エッジにカーソルを近づけると挿入位置が白い球で表示され、クリックするとエッジを分割してその位置にノードを入れます（属性は両側に引き継ぎ、distance_m は按分）
  - `E` エッジ追加：始点→終点の順にクリックします（続けてクリックすると連結されます）。種別は推測で入ります（階段同士なら stairs、車椅子不可）
  - `A` 入口紐付け：場所を選んでからノードをクリックすると place_access_nodes を作ります
  - `Del` 削除、`Ctrl+Z` / `Ctrl+Y` 元に戻す/やり直し、`Esc` 解除
- **マーカー前面**（ツールバー、既定でオン）：ノード・場所・エッジを建物より手前に描きます。クリックの判定も、建物モデル・階の面よりマーカーを優先するので、建物の中と外のノードを結ぶエッジや入口の紐付けで、建物に判定を取られません
- **視点**：ツールバーの「平行投影」で遠近感のない表示に切り替えられます（視点と大きさは引き継ぎます）。右下の軸表示は、X / Z を押すとその方向からの視点になります。**Y を押すと真上からの視点になり、既に真上からなら押すたびに90°回転**します（Y の反対側の小さい丸も真上からの視点）
- **2D平面図**：floorplanごとにSVGの上で map_x / map_y を手で置きます。左の「未配置」リストから選んでクリックで配置、ドラッグで移動します

## 高さの制約

- 同じfloorplanに属する場所（place_locations）と経路ノード（route_nodes）は、world_y が **そのfloorplanの高さに固定**されます
  - place_location の floorplan：`floorplan_id`、なければ `places.floor_id` の階の平面図（sort_orderが最小のもの）
  - route_node の floorplan：`floor_id` の階の平面図
- 高さは「平面図/高さ」タブで変更でき、変えると該当する行がすべて一緒に動きます
- 初期値は、既存データの中央値 → 同じ階のノードの中央値 → `(level_no-1) × 標準階高` の順に決めます
- 屋外（floor_id が NULL）の要素は自由に高さを決められます

## places や3Dモデルを差し替えたとき

- 新しいCSVやGLBをそのまま読み込み直してください。編集した5テーブルと高さの設定は残ります
- 「検証」タブで次のものを確認できます
  - 参照先が無くなった行（「孤立行を一括削除」で消せます）
  - 場所の階と平面図の階が食い違っているもの
  - `buildings.model_object_name` がGLB内に見つからないもの
  - 仕様書11章の制約違反
- エラーが残っている間は書き出しできません

## 補足

- 同じ名前の場所（トイレなど）は、一覧・Inspector に「建物 / 階 / [平面図名] / #部屋番号」を併記して見分けられるようにしています。3Dのラベルは名前だけにして階ごとに色分けし、3Dビュー左下に色と階の対応を出します。遠くのラベルは小さく表示します
- `fixtures/` には動作確認用のサンプルデータが入っています。`npm run fixtures:glb` でテスト用GLBを作り直せます
